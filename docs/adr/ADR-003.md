# ADR-003: Identity uses developer signing credentials only in development

## Status
Accepted

## Date
2026-04-02

## Context
Identity API configures Duende IdentityServer. Current code gates developer-only signing behavior with `builder.Environment.IsDevelopment()`: key management is relaxed in development and `AddDeveloperSigningCredential()` is only added for development. The production branch intentionally leaves a placeholder for secure signing key integration.

## Decision
Keep development signing credentials strictly development-only. For production, require managed signing keys from a secure store (for example Azure Key Vault-backed certificate/key material) and do not use developer credentials.

## Consequences
- Pros: Prevents accidental production use of ephemeral developer signing keys.
- Pros: Establishes a clear production hardening path for token signing.
- Cons: Production deployment now depends on external key provisioning and rotation processes.
- Cons: Startup/deployment fails fast if production signing material is not configured.

## Alternatives considered
- Use developer signing credentials in all environments: rejected due to security risk.
- Commit static signing secrets/certificates in repository config: rejected due to secret management risk.
- Delay production signing decision: rejected because token trust boundary requires explicit strategy.
